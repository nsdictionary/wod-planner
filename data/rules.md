# WOD 작성 규칙

- 최종 갱신: 2026-11-07
- 근거: 기획서(https://gist.github.com/nsdictionary/36fa6d76c435011389a925ed4012ef3c) + 코치 확정 사항
- 표기: **[코치 확정]** 코치가 확인한 운영 규칙 / **[기획서]** 기획서 본문 명시 / **[기획서 예시]** 예시 WOD에만 등장, 규칙 아님 / **[미확인]** 값 없음

## 1. 시간 기준 [코치 확정]

| 항목 | 기준 |
|------|------|
| 그룹 수업 | 일반적으로 60분. WOD 외에 복싱, 스트렝스, 악세서리 운동, 웜업, 설명, 쿨다운 등 |
| **WOD 본운동** | **최대 30분**. 웜업·설명·쿨다운은 포함하지 않는다 |
| AMRAP / EMOM | 설정된 진행 시간이 본운동 시간 |
| For Time | **TC**가 본운동 시간. TC가 없으면 30분 검증을 할 수 없으므로 TC를 반드시 정한다 |

- MVP는 **WOD 본운동 시간이 30분 이하인지**를 검증한다.
- 60분 전체 수업 구성은 요청 시 응답에만 표시한다. 블록 합계 = 수업 시간, WOD 블록 ≥ 본운동 시간을 `scripts/check_class.py`가 검증한다. 본운동 30분 상한과 수업 시간은 따로 관리한다.
- 코치가 "18분 이내"처럼 본운동 상한을 따로 요청하면 초안 `max_workout_min`에 적고, 30분과 둘 중 작은 값으로 검증한다.
- 기획서 예시의 웜업 7분 / 설명 4분 / 쿨다운 5분은 **예시일 뿐 규칙이 아니다**. [기획서 예시]

## 2. 시간 표시 원칙 [코치 확정]

시간 관련 출력은 아래 네 가지 상태 중 하나로 표시한다. 계산하지 않은 값을 계산된 것처럼 보이게 하지 않는다.

| 상태 | 뜻 | 예 |
|------|----|----|
| **검증됨** | 데이터 없이도 결정적으로 확인되는 값 | `AMRAP 12 → 본운동 12분 ≤ 30분` |
| **추정** | 근거 있는 추정 범위로 계산한 값. 범위와 근거를 함께 표시 | `라운드당 2:10~2:50 (근거: 동작별 범위 × 횟수 + 전환)` |
| **추정 불가** | 추정에 필요한 데이터가 없음. 없는 항목을 나열 | `라운드 시간 추정 불가: Toes-to-Bar, Box Jumps 시간 데이터 없음` |
| **확인 필요** | 코치가 답해야 하는 항목 | `박스 보유 수량 확인 필요` |

- 시간 데이터가 없어도 **WOD 생성과 본운동 30분 검증은 가능**하다. 라운드 시간·예상 라운드·예상 완료 시간만 "추정 불가"가 된다.
- 에이전트는 시간을 암산하거나 그럴듯한 값을 지어내지 않는다. 추정은 스크립트 결과만 인용한다.

## 3. 시간 추정 모델

1rep 시간은 고정값이 아니다. 회원 수준, 반복 수, 피로도, 전환 시간에 따라 달라진다.

- **회원 수준:** 동작별 `time_estimate.sec_per_unit`을 단일 값이 아닌 `low`~`high` 범위로 둔다 (`data/movements.json`).
- **반복 수:** 라운드 시간 = Σ(reps × 범위). 반복 수가 많을 때 세트를 나눠 느려지는 효과는 아직 모델에 없다. 실제 결과로 보정한다(Post-MVP R9).
- **피로도:** 라운드가 진행될수록 느려지는 비율. 근거가 없으므로 `null`. `null`이면 추정 결과에 "피로도 미반영"을 함께 표시한다.
- **전환 시간:** 동작 사이 이동·장비 전환 시간 범위. `null`이면 라운드 시간은 "추정 불가".
- 추정에 필요한 값(해당 WOD의 모든 동작 `time_estimate`, `transition_sec_range`) 중 하나라도 `null`이면 그 WOD의 라운드 시간은 "추정 불가"다.

## 4. 기계 판독 설정

스크립트는 이 파일의 **첫 번째 `json` 코드 블록**만 읽는다. `null`은 미확인 값이다.

```json
{
  "class_total_min": 60,
  "workout_max_min": 30,
  "workout_time_basis": {
    "AMRAP": "duration_min",
    "EMOM": "duration_min",
    "FOR_TIME": "time_cap_min"
  },
  "estimation": {
    "transition_sec_range": null,
    "fatigue_slowdown_per_round": null
  },
  "recent_days": 7,
  "patterns": ["pull", "push", "legs", "cardio"],
  "supported_formats": ["AMRAP", "EMOM", "FOR_TIME"]
}
```

- `class_total_min`: 참고값. MVP 스크립트는 사용하지 않는다.
- `workout_max_min`: 본운동 상한. [코치 확정]
- `workout_time_basis`: 형식별로 본운동 시간으로 쓰는 초안 JSON 필드. [코치 확정]
- `estimation.transition_sec_range`: `{"low": 초, "high": 초}` 형식. [미확인]
- `estimation.fatigue_slowdown_per_round`: 라운드당 느려지는 비율 범위. [미확인]
- `recent_days`: 최근 기록 조회 기간. [기획서]
- `patterns`: 당기기(pull)·밀기(push)·하체(legs)·유산소(cardio). [기획서]

## 5. 작성 규칙

- 화이트보드에 옮겨 쓸 수 있는 **plain text**로 쓴다. [기획서]
- 성인 WOD는 **영어**, 키즈 WOD는 **한국어**로 쓴다. [기획서]
- 설명, 경고, 시뮬레이션 근거는 한국어로 쓴다.
- 바벨 무게는 **lb**, 덤벨 무게는 **kg**로 쓴다. [기획서]
- 남/여 기준은 `24/20 in`처럼 슬래시로 구분한다. [기획서 예시]
- 셔틀런은 `Shuttle Runs (15m = 1 rep)`처럼 1rep 거리를 표기한다. 1rep = 7.5m 왕복 = 15m. [코치 확정]

## 6. 장비·공간 규칙

수량과 보유 여부의 기준은 `data/equipment.json`이다. 이 파일에는 수치를 복사하지 않는다.

**확정 규칙**
- 미보유(`available: false`) 장비가 필요한 동작은 WOD에 넣지 않고 대체 동작을 제안한다. [기획서]
- 보유 여부·수량·규격이 `null`인 장비를 쓰면 "확인 필요"로 표시하고 코치에게 묻는다. 수량이나 규격을 추측하지 않는다. [코치 확정]
- 바벨·원판은 lb, 덤벨은 kg로 기록하고 표기한다. [기획서]

**수량 정확도와 경고** [코치 확정]

수량은 `{"value", "precision"}`으로 기록한다. "약 8명", "여러 개"를 정확한 정수로 바꾸지 않는다.

| precision | 뜻 | 검증 출력 |
|-----------|----|----------|
| `exact` | 정확한 수량 | 경고 없음. 필요 수량 > 보유 수량이면 "부족" |
| `approx` | "약 N" | **추정 수량 경고**: "약 N(추정) — 실제 수량 확인 권장". 필요 수량이 N 근처면 부족 가능성 경고 |
| `unknown` | 보유하지만 수량 미확인 | **수량 미확인 경고**: "보유, 수량 미확인 — 인원 대비 충분한지 코치 확인 필요" |

**공간 제약** [코치 확정]
- **층고:** 낮다. `movements.json`의 `space_tags`에 `high_ceiling`이 있는 동작(링 머슬업 등)은 WOD에 넣지 않고 대체를 제안한다. 링 자체는 보유하므로 높은 공간이 필요 없는 링 동작은 가능하다.
- **월볼 타깃:** 벽면 약 2.3m, 표준 높이 타깃은 쓸 수 없다. 월볼은 성인 수업에서 사용할 수 있지만, WOD에 넣을 때 타깃 높이(약 2.3m)를 함께 표기하고 "표준 타깃 아님" 경고를 표시한다.

**고정 규칙이 아닌 것** [코치 확정]
- 셔틀런 레인 분리와 장비 부족 시 교대 방식은 WOD 구성과 인원에 따라 달라진다.
  에이전트는 필요 수량 대비 보유 수량을 보여 주고, 운영 방식(레인 분리, 2인 1조 교대, 시차 출발 등)은 **선택지로만 제안**한다.
- 참고 사례: 기획서 예시의 "6명 이상 2레인", "박스 부족 시 2인 1조 교대" (`equipment.json`의 `operational_examples`). [기획서 예시]

## 7. 최근 기록과 패턴

- 최근 7일 WOD(`wods/`)를 읽고 패턴(pull, push, legs, cardio)이 겹치는지 확인한다. [기획서]
- 주간 플랜이 없으면 최근 기록만으로 판단한다. [기획서]
- 동작별 패턴은 `data/movements.json`의 `patterns`를 따른다. 지금 값은 초안이라 코치 확인이 필요하다.

## 8. 출력 형식 (기획서 결과물 예시를 기반으로)

```
WOD - AMRAP 12
10 Toes-to-Bar
15 Box Jumps (24/20 in)
20 Shuttle Runs (15m = 1 rep)

[시뮬레이션]
- 본운동: AMRAP 12 → 12분 ≤ 30분 (검증됨)
- 라운드당: 추정 범위와 근거, 또는 "추정 불가: <없는 데이터>"
- 장비: 필요 수량 vs 보유 수량, 미확인이면 "확인 필요", 부족 시 운영 선택지
- 특이 회원: 대체 동작
- 최근 기록: 패턴 중복 여부
```

- 기획서 예시의 "라운드당 약 2분 30초 → 4~5라운드"는 근거 데이터가 없는 예시 수치다. 그대로 쓰지 않는다.
- 성인 WOD는 Rx + Scale A/B/C를 만든다(초안 `scales`, 사용 가능 여부는 `check_equipment.py`가 검사). 키즈 버전은 Post-MVP다.
